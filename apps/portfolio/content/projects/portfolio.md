## 1. 프로젝트 개요

- **배경 및 목적**: 기존 Flutter Web의 큰 초기 번들 사이즈와 SEO 취약점을 극복하면서, Dart 생태계의 컴포넌트 모델과 상태 관리 체계를 그대로 활용할 수 있는 현대적인 반응형 포트폴리오 웹사이트를 구축하고자 시작하였습니다.
- **핵심 목표**: 순수 HTML/CSS 렌더링을 통한 가벼운 웹 성능 확보, 콘텐츠 유지보수를 최소화하는 데이터 주도 구조 설계, 그리고 AI 피드백 체계 통합.

## 2. 담당 역할 및 핵심 기능

- **담당 역할**: Melos 기반 모노레포 아키텍처 설계, Jaspr 컴포넌트 개발, 반응형 UI/UX 구현, AI 에이전트 하네스 구축 등 전체 1인 전담 개발
- **핵심 기능 목록**:
  - **반응형 포트폴리오 & 이력서 뷰어**: 모바일 및 데스크톱 뷰포트에 최적화된 프로젝트/경력 정보 UI
  - **Configuration Driven Development (CDD)**: 마크다운 및 YAML 데이터 기반 정적 콘텐츠 자동 파싱 및 렌더링
  - **AI 에이전트 이력서 하네스 구축**: Antigravity 기반 개발자 이력서 피드백을 지원하는 하네스 구축

## 3. LLM 활용 방향 및 범위

- 처음 프로젝트를 수행할 때는 아직 LLM 초창기라 활용에 신중했기에 사용하지 않고 개발하였으나, 이후 기술 발전으로 효용성이 충분해졌다 판단해 유지보수 등을 시작으로 점진적으로 LLM을 통한 코드 작성을 시도하였습니다.
- Dart, Jaspr, Web 등 다양한 도메인에 에이전트 스킬을 설치하고, 이를 통한 전반적인 코드 및 아키텍처의 개선 작업을 진행하였습니다.
- 이력서의 관리 및 웹 서빙이란 프로젝트의 본 목적을 넘어 서브에이전트와 스킬 등에 기반한 하네스를 작성해 저장된 이력서 내용을 LLM 피드백 및 수정하는 플로우를 구축하였습니다.

## 4. 핵심 의사결정 및 문제 해결

### 1) Flutter Web 대신 Jaspr 웹 프레임워크 도입

- **상황 및 과제**: Dart/Flutter 개발 경험을 살리면서도 일반 웹 사용자에게 빠른 초기 로딩 속도와 SEO를 제공해야 했습니다.
- **기술적 의사결정**: Flutter Web은 Canvas/Wasm 기반으로 렌더링되어 번들 사이즈가 크고 SEO에 제약이 있는 반면, Jaspr는 Dart 언어를 사용하면서도 브라우저 표준 HTML/CSS를 직접 출력하는 SSR/SSG을 지원하여 웹 표준과 생산성을 동시에 만족했습니다.
- **구현 및 해결**: Jaspr를 도입하고 Tailwind CSS를 결합하여 스타일링 시스템을 구축하였으며, Riverpod을 통해 상태를 모듈화하였습니다.
- **결과 및 영향**: 기존 Flutter Web의 한계를 극복하여, 번들 크기를 경량화하고 순수 시맨틱 HTML/CSS 기반의 빠른 렌더링과 뛰어난 검색 엔진 최적화(SEO)를 달성했습니다.

### 2) Configuration Driven Development (CDD) 아키텍처 설계

- **상황 및 과제**: 새로운 프로젝트나 경력 이력이 추가될 때마다 파편화된 Dart 컴포넌트 코드를 직접 수정해야 하는 비효율을 제거하고 싶었습니다.
- **기술적 의사결정**: 데이터와 코드를 엄격히 분리하여, 마크다운과 YAML 설정 파일만 업데이트하면 빌드 타임에 자동으로 적용되는 구조를 설계했습니다.
- **구현 및 해결**: `content` 디렉토리에 프로젝트 및 이력서 콘텐츠를 파일 단위로 배치하고, `dart_mappable`과 마크다운 렌더러 컴포넌트를 통해 메타데이터와 본문을 동적으로 결합하도록 구성했습니다.
- **결과 및 영향**: 새로운 경력이나 프로젝트가 추가될 때마다 Dart 코드를 직접 수정하던 비효율을 제거하고, 마크다운/YAML 파일 수정만으로 빌드 타임에 자동 반영되는 유지보수성 높은 데이터 주도 환경을 구축했습니다.

## 5. 주요 성과

- CDD 기반 확장성 있는 반응형 웹 포트폴리오 완성 및 Docker 기반 배포 환경 구축
